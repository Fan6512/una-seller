## 0. 结论速览

1. **采集逻辑全部在插件本地**：`assets/js/content.js` 用一套很长的 CSS 选择器兜底链，在 amazon.com 页面 DOM 上直接解析出商品字段；`assets/js/background.js` 另有独立的 HTML 抓取 + linkedom 解析器。**不是**把整页 HTML 上传给服务端再解析。
2. **两条数据通道**：
   - DOM 通道：content script 消息 `AMZ_PARSE_REQUEST` → 本地 `AMZDetailDomParser` → `AMZ_PARSE_RESULT`；
   - 后台通道：`type 3 (ASINPARSEITEM) / 24 (ASINDETAIL) / 241 (ASINSDETAIL)` 任务队列 → `fetch("${origin}/dp/${asin}?psc=1")` → DOMParser / linkedom 兜底解析。
3. **单品入库链路**：`spider.check`（防重）→ `amazon_hub.spider`（取采集参数）→ `spider.insert`（提交 `sale_*` 字段）。域名 `seller.zying.net/api`；另有 `amazon.zying.net/api` 提供竞品价、限制、账号等辅助接口。
4. **所有 API 请求被 WASM 签名**：`assets/img/static-chunk.png` 是伪装成 PNG 的 AES-GCM 加密 WASM 容器，加载器同时内联在 `content.js` 侧的 `chunk-common.js`（模块 86814）和 `background.js`（模块 7175）中，两个上下文都能签名。
5. **附带 GA4 遥测**：`background.js` 把 `feature_usage` 事件上报到 Google Analytics Measurement Protocol，`api_secret` 硬编码在源码里。
6. **对比**：`kuajing-erp-plugin-v3-5x` 走相反路线——运行时从远程 CDN 下载入口脚本注入主世界，把 `document.documentElement.innerHTML` 整页上行，服务端解析（详见 `03_…md`）。

### 3.3 详情页字段解析（核心）

#### 3.3.1 解析入口【源码】

`AMZ_PARSE_REQUEST` 由后台发到 content script，content script 调用 webpack 模块 `79667` 的 `AMZDetailDomParser`：

```js
"AMZ_PARSE_REQUEST" === e.type && e.messageId && e.data
  ? (setTimeout(() => {
      let HTML = e.data?.HTML;
      try {
        let {asin, lan, site} = e.data || {};
        let {AMZDetailDomParser} = l(79667);
        let s = AMZDetailDomParser(asin, HTML, lan, site);
        f({type:"AMZ_PARSE_RESULT", messageId:e.messageId, data:s, fullUrl:location.href});
      } catch(t) {
        f({type:"AMZ_PARSE_RESULT", messageId:e.messageId,
           data:{success:false, error:String(t), asin:e.data?.asin},
           fullUrl:location.href});
      } finally { HTML = null; e.data && (e.data.HTML = null); }
    }, 0), sendResponse(true), {handled:true, responseSent:true, shouldStop:true})
```

`79667` 只是转发：`n=(e,t,l,r)=>(0,i.u)(e,t,l,r)`，真正实现在模块 `22516`（含 Unicode 清洗 `a()`、`d()`/`c()`/`u()` 等 helper）。模块 `79667` 还导出 `getJSON(document)`，供「复制子 ASIN」等功能读取页面脚本里的 twister 数据。

### 5.3 请求签名与隐藏 WASM

**容器**：`assets/img/static-chunk.png`，44900 字节，SHA-256 `8e6b08dfb1e05c419f9fc3731285dd48e8e95541936f155811439a2ac5b3dd9c`，与源码常量 `{"v":1,"h":"…","n":44900}` 一致；魔数 `ZYWASM1\x01`。

```
[ magic 7B ][ ver 1B ][ IV 12B ][ GCM tag 16B ][ AES-256-GCM 密文 … ]
            └──────── AAD = 前 20 字节 ────────┘
```

- 密钥：两段常量字节经 `p[t] ^ m[7&t] ^ ((13*t+7)&255)` 混淆后，取 `SHA-256` → `importKey("raw", …, "AES-GCM", false, ["decrypt"])`。
- 解密结果 44864 字节，WASM 魔数 `00 61 73 6d 01 00 00 00`，`WebAssembly.validate === true`，导出 `memory / a / d / p / s / u / _dk0 / _dk1 / __data_end / __heap_base`，无 imports。

**签名生成**【源码】：

```js
n.set([90,83,71,49,2], 0);              // "YSG1\x02"
let fields = [body, method, path, timestamp, token];  // 5 个长度前缀字段

```

**请求头**【源码】：`token`、`appclient="3"`、`timestamp`、`signature`、`version="v1.1"`、`client_identify`、`ext_version`（DES-CBC 解 `5rgfRGVKrS0=`，key `acc67e85`，iv `4c2b3d81f0e04abe81481e4ce61de9bb`）。

**完整性与缓存**【源码】：
- `localStorage.rt_integrity`：`off / soft / strict`，控制哈希/长度不符是忽略、告警还是抛 `E1097/E1098`；

### 7.2 必须保留的限制

1. **no-match ≠ 功能不存在**。`api:fetch`、`channel:AMZ_PARSE_REQUEST`、`string:spider` 全部无匹配，因为 REA 把 JS 当惰性文本、webpack 图只保留 `imports / contains / persists_to / calls / exposes` 关系，URL、`cmd=`、DOM 选择器都是普通字符串字面量而非 typed 节点。

   - `https://www.google-analytics.com/mp/collect?...`
   - `https://seller.walmart.com/aurora/v1/items`（Walmart 平台，非 Amazon）
   以及 `https://h5api.m.taobao.com/h5/mtop.common.gettimestamp/1.0/?...`（淘宝时间戳）。
4. `source_paths` 只选了 1–2 个文件，34/35 个未选（`inject-*.js`、`landing.js`、`aiPricing.js` 等），语义图 `truncated: true`。
5. 所有 trace 均为 `confidence: inferred`、`authority: analyst-inference`、`coverage: partial`。
6. 【REA observed】`content.js` 终结点里的 `MELI_*`、`CURRENT_MARKET`、`TMX_DATA`、`/tracker` 路由说明这是一个**多平台通用注入脚本**；`passkey-inject.js`（MAIN world）是 Seller Central 的 WebAuthn/passkey 桥，带 iframe sandbox 检测与域名白名单，与商品采集无关。
