# ADR-0002：数据与任务按需引入，避免过早建设同步平台

- 日期：2026-10-26
- 更新：2026-10-26（简化修订）
- 状态：**Accepted as lean baseline**

## 决策

- 初期一个 **Supabase 托管 PostgreSQL** 数据库，**只建立真实功能需要的表**；在 M0-02 涉及持久化时再创建/接入。Go 服务端作为已保存业务数据的访问边界，桌面端不直接连接数据库。
- 桌面本地先不持久化全量业务内容，需要草稿和检索时再加 SQLite；SQLCipher 在确需敏感离线数据时验证。
- 少量任务先用简单实现，涉及外部写入与失败恢复时使用持久任务；River、Redis、Event Bus 和数据仓库都不是 M0 依赖。
- 跨设备先保证重新登录后能读取云端已保存数据；完整双向离线同步、快照与游标待真实需求出现再做。

## 保留的底线

外部写入不可仅凭超时结果盲目重试；同一操作必须有可查记录与回读。金额精确存储；Token 服务端保密。跨设备离线草稿不会自动恢复，也不能假设远程吊销可立即清除离线缓存。

## 升级条件

当实际出现积压任务、重复操作、并发冲突、离线编辑或缓存性能问题，再基于复现数据引入相应技术；不得为了未来的预期规模提前建立分布式系统。
