# ADR-0001：桌面跨平台与单体优先；M0-03 后端 Go 选择

- 日期：2026-10-26
- 更新：2026-11-15（M0-03 执行选择修订）
- 状态：**桌面技术确定；当前唯一业务后端采用现有 Go 服务（阶段性执行决策），出现实际阻塞再评估。**
- 适用：Una Seller 自用优先、只支持 Mercado Libre。

## 决策

- Windows/macOS 客户端采用 Tauri 2 + React + TypeScript (strict)，仅保留必要 Rust 原生代码。
- 服务端从**一个简单 Go HTTP 应用**开始，复用仓库现有 `backend/cmd/api`。该选择基于当前已有代码与减少重复实现，**没有声称完成 Go/TypeScript-Fastify 的性能或开发成本实测比选**。当前不并行实现另一套服务；出现有证据的阻塞再修改 ADR。
- 初期不拆微服务，不创建独立 AI 进程、独立身份系统、事件总线。
- 是否提前使用 OpenAPI SDK 生成依据重复类型与契约变化成本决定；最初可使用小型、明确定义的接口。

## 理由

跨平台是确定的硬需求；性能瓶颈还没有实测。单人早期研发最重要的是简单、可测、可部署，不是构建复杂技术栈。

## M0-03 执行验收

使用现有 Go `/healthz`，增加 PostgreSQL 迁移和商品采集 POST/GET，让 Windows/macOS Tauri 采集箱读取真实商品；以此验证能否满足当前实际需求。不因理论性能比较推迟 M0-03；若实际搭建/运维成本出现阻塞，再重新评价 Go 与其他候选技术。
