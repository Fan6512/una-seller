## 操作入口

```sh
una-seller-api cbt-categories review -build-plan -full-path -budget 900000 -seed tr02e-v1
una-seller-api cbt-categories review -build -full-path -budget 900000 -sample 200 -seed tr02e-v1
```

每批1–200条；scope all，完整路径，不能混用 trial/import/exclude-ids。每批先在同一 update.lock 下加载当前快照、人工覆盖、术语及已完成候选，预检**全部剩余**字符是否可在预算内完成。现有非完整路径候选阻塞全量，需归档复核；不静默降级。全程持有同一普通更新锁及 LLM run lock，阻止 update/import/trial 并行写入；每条仍按已有独立额度锁在发送前预扣。每条一次请求、1秒间隔、15秒超时。

成功译文逐条原子保存至原 llm-review-candidates.json；重启按已存候选跳过，无需重跑。结构正确但不符合语言要求的非中文译文，写入独立 llm-build-deferred.json（版本/ID/完整q SHA256），不写候选，后续发布仅能按官方英文回退或经人工确认修正。未知非中文专名不直接接受。结构错误、网络、鉴权、限额或存储异常立即停止。

每次真实请求前保存 llm-build-pending.json（版本、ID、源哈希、源字符、累计用量），提交候选或延期记录后删除。异常或强杀留下 pending，后续禁止自动发送；现场核查对应已提交候选/延期记录、控制台及额度，归档原 pending（不修改计数），确认是否需要人工修正或明确重试后再继续。不能用删除 pending 来绕过额度保护。成功/延期的逐条回执另追加至 llm-build-receipts.jsonl 并 fsync，之后才清除 pending；错误或尾部截断保留 pending 并停止，现场核对后归档。旧 trial 同样检查未解决 pending，额度对账须取得 LLM run lock，避免与批次并发。命令标准输出仍按批归档。硬断电目录fsync及强杀时 stdout 不完整是已知限制；pending/候选/用量三者须核查。逐条保存全量候选文件沿用现有原子写入，避免反复读取快照，仍有磁盘写放大；实测性能不足时再优化日志压缩/批量落盘。
