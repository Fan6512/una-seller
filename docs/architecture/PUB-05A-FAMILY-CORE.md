# PUB-05A 单店单站点多变体 Family 刊登核心

[Issue #50 负责人范围](https://github.com/Fan6512/una-seller/issues/50#issuecomment-7192167415) · [C0 合同与身份设计](CBT-PUBLISH-C0.md)

## 首个可运行切片

产品箱以一件已保存产品、一个归属店铺和一个已验证 Remote 站点为输入。服务读取已保存的英文 Family 名、CBT 类目、正式描述、每规格 SKU、库存、采购成本、目标净收益及官方图片 ID。以两个模拟规格走通一次准备、模拟创建和回读。使用现有 Go 测试与模拟 HTTP 服务，生产写入需针对具体对象单独批准。

1. **编辑与身份。** 现有 `ListingVariant` 缺少稳定 ID 与独立库存。由服务端分配不可变变体 ID，区分库存未填和库存为 0。改 SKU、规格或排序时按 ID 保持同一变体。已有草稿在一次显式保存中补齐身份，缺失 ID 的旧客户端沿用现有冲突保护。歧义变体须人工确认归属。无显式变体时复用单规格固定键。
2. **准备。** 从已有店铺授权及映射校验店铺、站点、Remote 物流和 Standard UP / Net Proceeds 能力。使用当前类目定义校验 PARENT_PK 一致、CHILD_PK 字段完整、组合唯一。使用规范化官方属性值比较，保留官方 ID 与单位。正式描述取产品箱已审核内容。只接受已取得并归属当前范围的官方图片 ID。
3. **请求。** 复用同一准备过程为每规格生成一份 UP 数据。新多规格 Family 使用 `POST /global/user-products/families`，为每个数组元素使用同一英文 `family_name` 和一个 `sites_to_sell` 站点，保留独立库存、净收益、图片和属性。传统 `variations[]`、`title` 与本地成本字段不进入官方请求。单规格按 C0 使用 `POST /global/items`，复用属性、图片和销售条件校验。[官方变体合同](https://global-selling.mercadolibre.com/devsite/en_us/pricing-reference/price-per-variation-cbt)
4. **防重与回读。** 按 C0 既定模型，在发送前持久化 Family、变体、站点身份和同一创建尝试。按产品/店铺/变体作用域拦截并发与重复提交。回读核对同一 Family、各自 UP ID、站点 item ID、子卖家、站点与物流。回包缺项、超时、响应丢失或身份歧义保留 `pending_verify`，通过可信回读解除。部分结果分规格保存，后续核实已存在的主体及站点，避免整批重发。

## 模拟验收

| 场景 | 可检查结果 |
| --- | --- |
| Red / Blue 两规格，同一 Family 名、类目和 PARENT_PK，各自库存与净收益 | 一个 Family 请求、两个独立 UP 条目、一个目标站点。模拟回读得到同一 Family ID、两组不同 UP / item ID，并按本地变体 ID 保存。 |
| 改 SKU、重排、旧草稿补齐 ID | 工作台成本及已有官方映射仍跟随原变体。无法识别的旧编辑返回显式冲突。 |
| PARENT_PK 不一致、CHILD_PK 组合重复、图片只有 URL，或站点不属于店铺 | 准备失败，模拟写入调用为零。 |
| 重复提交、并发提交、超时后点击重试、部分回包 | 同一创建意图至多发送一次，未知项进入待核实，匹配的官方 ID 保留。 |
| 单规格 | 经同一准备过程生成单个 UP，模型路由与模拟回读通过。 |

## 开发顺序与决策

完整实现需要同时覆盖旧草稿兼容、产品身份与库存、店铺权限、发送前持久化和官方回读，因此会跨现有产品保存、刊登服务和数据库模块。准备、提交与回读使用同一组稳定身份，代码评审重点核对旧客户端和未知创建结果两条路径。独立 Draft PR 首先固定这份实施基线。

可先做更小的可运行切片，在已有产品箱数据上生成离线预览，用两规格模拟夹具校验类目分组和请求体。该切片不依赖数据库迁移，用于验证准备合同。持久身份、防重、回读及真实刊登仍需要完整方案。

本轮 D2 已独立收口。PUB-05A 开发无需等待 WH-06 D1 真实推送；真实商品创建、图片上传、发布部署仍需单独批准。多店多站点归 PUB-05B。


## 2026-11-26 审查裁决：分步实现完整核心，不以预览代替刊登

- A1：先实现可复用、无远端副作用的准备器与请求构造（同一代码服务单规格/多规格），用两规格合成夹具对照官方文档；预览只是调试手段，不另建一套前端 JSON 编辑器，不单独声称 PUB-05A 完成。
- A2：在现有工作稿/产品箱保存链路加入服务端稳定变体 ID 和可空独立库存；优先复用现有 listing_fields JSON 持久化，不为此单独建变体表。编辑重排/改 SKU 不改变身份，旧客户端兼容需按现有冲突保护处理；未知/重复 ID 不能冒充另一变体，不能凭数组下标或可变 SKU 重绑。无变体沿用固定内部键。仅在身份持久化通过后接线 A1。
- A3：复用已有 Go 鉴权/类目/HTTP 协调机制，按 C0 身份与尝试设计提交最小私有迁移，真实上传/创建前持久化请求意图、固定目标与精确 payload 摘要；网络调用在短事务之外，回包按请求身份条件回写。保留未知结果，只有明确未创建的目标才允许人工重试。模拟一次 Family 创建及两规格回读；不引入新任务平台。一个 Draft PR 内分提交，必要时按实际变更范围拆小但不丢业务闭环。
- 官方合同以 [User Products](https://global-selling.mercadolibre.com/devsite/user-products-cbt)、[Price per Variation](https://global-selling.mercadolibre.com/devsite/price-per-variation-cbt) 为准。Remote Family POST 的公开示例根级为数组，元素含 `family_name`、`category_id`、数值 `global_net_proceeds`、`available_quantity`、纯文本描述、官方图片 ID、属性和目标站点。金额不得经过浮点四舍五入；不将本地 ID、采购成本、传统 `title`/`variations` 传入官方。SKU 具体写入字段、可写权限、必填/尺码表、数量/金额边界及回包关联仍需按官方合同和真实只读证据核实，不猜测。所有规格同一基础英文名称、类目和规范化 PARENT_PK；CHILD_PK 按真实类目定义校验，不虚构所有类目均需颜色/尺寸。无法支持的类目明确阻断。
- 回读明确区分 Siteless Family ID 与本地站点 Family ID、Siteless UP ID 与站点 UP/item ID，均保存为字符串，不能凭回包数组顺序匹配规格。依据已验证的 SKU/官方属性等唯一证据映射；缺失/歧义保留 pending_verify。新增规格到已有 Family 的接口不同于创建新 Family，暂不开放，不整批重发。
- 最小验收沿用本仓库 CI：两规格正确构造和回读、稳定 ID 重排/改 SKU、关键必填/归属拒绝、未知/部分结果防重；不建立大型测试框架，不重复客户端视觉验收。真实官方图片上传、创建及生产部署仍单独获批。

D2 首轮生产已 PASS；远程 20:54 复核 53 个订单补偿、20 个货件补偿、5 个发现断点首窗均完成，活动/死信/冷却/回放均 0。真实 D1 仍 NOT_RUN，不阻塞本 PR。

## A3 持久化与模拟验收入口

- 产品箱“准备刊登”只列出可信输入表授予的目标和已有尝试。受控输入记录绑定 owner、产品及 revision、店铺、实际主/子卖家、站点、销售类型、每个稳定变体的官方图片 ID 和批准截止时间。单规格图片键为 `single`。没有记录时客户端无法创建，采集图片 URL 也不会被用作官方图片 ID。数据库记录由获批的服务端流程或操作人员登记，本切片提供读取和使用链路。
- Go 使用当前授权、站点计价和刊登额度、CBT 属性及技术规格准备请求。分类不明确、图片缺失，或规则要求尚未支持的条件属性和尺码表时，创建会被拦截。创建后按候选 ID 回读，单独展示身份及标题确认结果。缺失可信候选的尝试会继续显示待核实。已有尝试占用产品/店铺范围，且占用的变体 ID 在产品保存时受数据库保护。
- `0021_cbt_publication.sql` 是增量迁移。回滚应用版本可保留三张私有表和身份保护，以便继续恢复已登记意图。应用回滚无需删除表或清除尝试。
- `TestProductPublicationPostgresHTTP` 使用隔离 PostgreSQL、已保存产品和模拟官方 HTTP 核对三个刊登策略场景、精确请求体、逐变体身份、重复与并发确认、响应丢失、部分结果及标题未生效。官方图片归属、写入权限和回读响应形状的真实账号验收仍待独立批准。
