# WH-06 ACK 延迟修复与现场验收

## 事实与边界

2026-11-26 23:57:25（北京），真实货件对应窗口 Nginx 五字段日志为 HTTP/upstream 503/503、0.351/0.351s。持久收件、货件快照及订单缓存写回有数据库证据，但无法逐请求证实是否为同一投递，具体失败阶段仍未知。不能把该样本记为 HTTP 200 PASS。[夜间回执](NIGHT-PREFLIGHT-20261127.md)

官方 [接收通知](https://global-selling.mercadolibre.com/devsite/receive-notifications) 要求500ms内200。保持持久提交后才 ACK，禁止以内存队列或提前200绕过。仅将 Go body+DB 总预算从350ms调到400ms，保留约100ms代理/传输余量（不代表实际公网时延已达标）。8并发、16KiB、可信代理来源、私有令牌、主题、同步提交、授权、全局事务准入锁、原有容量/去重及 generation 更新不变。

## 最小改动

- 将事务内同步提交设置与同一准入锁合并为一次SQL往返（两个表达式均完成才读取授权及容量，锁仍持有至提交/回滚）。不引入新库、迁移、缓存或持久队列。
- 仅实时 Enqueue 显式获取连接/开启事务/提交；成功与重复通知都须得到提交确认。失败仍按原状态返回403/503；提交结果未知不能提前200，后续同一通知重试沿用原去重。补偿和回放仍调用原事务入口，仅复用等价的合并设置/锁语句。
- 对实时持久化失败及耗时至少200ms的成功收件，在 Go 服务日志输出固定阶段、脱敏结果类别及毫秒耗时。阶段 acquire、begin、admission、scope、dedupe_capacity、write、commit、committed。客户端侧阶段耗时含网络/驱动，失败最后阶段可能含清理；不输出请求体、事件/资源/店铺ID、令牌、原始SQL错误或IP。现有 Nginx 五字段日志保持不变。

## 验收

现有隔离PG HTTP并发、去重、授权、写入锁、容量、Worker等测试继续执行；新增同一准入锁被占用时返回503且无持久收件，释放后相同货件重试200、重复投递200且仅一收据/一代作业。CI 为隔离环境，不能冒充公网验证。

现场使用固定候选及隔离 PG17.11，尽量复用实际数据库连接网络路径的独立隔离数据库（不得对生产注入通知），检查正常/重复 ACK、慢/失败阶段、Nginx与Go预算，必要时量化RTT。生产部署仍须获批；保持自动补偿及其他配置。等待自然真实通知并对照五字段日志及数据库消费，HTTP 200且总耗时<500ms才记真实ACK通过。若仍失败，根据阶段定位，不盲目增大超时；不伪造生产请求、不变更订阅、不触发历史回放。不将旧503样本改记PASS。
