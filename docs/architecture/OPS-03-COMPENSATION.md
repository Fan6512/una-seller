One page (3 pack envelopes, at most 120 IDs) per minute across the single process, persist exact IDs before draining up to 8 per tick. Already-local or durable active/recent-dead work covers a discovered ID; otherwise admit with compensation provenance and exact scope. Capacity/cooldown is NOT success. Advance page only after all IDs have durable outcomes; window only after final page. A crash between enqueue and cursor update replays the same IDs safely. No provider call under discovery transaction, no new worker system, no raw search payload, no manual cursor writes. Known-resource sweep still runs separately (up to 8 hints/minute); includes payment-pending status so a lost paid transition can be corrected. Max 16 new hints/minute across both sweeps, backlog gate 32, shared rate coordinator and single scheduler. Existing login health check remains; continuous server discovery does not depend on login. Desktop now reads the first idle order page's local cache every 30 seconds while visible; no official search, manual cursor reload, dialog interruption, or automatic image restart. Hidden window/settings, active search/pagination, busy action or dialog stop polling. Local errors retain the last visible snapshot. Windows/rapid-navigation UI acceptance is pending. Default disabled.

Limitations: malformed/unstable provider pages retain checkpoint (no automatic skip); monitor stuck windows before activation. Initial history older than 24h is manual sync territory. No guarantee of recovering events outside API retention/overlap. Current authorization and mapping checked before search and before admission/progress. A dead-letter remains an unresolved event, not a successful order sync.
