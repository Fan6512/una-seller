## Phase B — bounded operator replay candidate

Official contract reference: https://global-selling.mercadolibre.com/devsite/en_us/validations-cbt/receive-notifications (updated 2026-09-14). Topic-filtered GET /missed_feeds supports limit/offset. Actual history result ordering, retention, and pagination behavior still require live read-only validation. Do not assume a snapshot or promise zero omissions.

0020 adds missed_feed provenance and a checkpoint per application, topic and credential store. The command `api missed-feeds-replay OWNER_UUID STORE_UUID TOPIC` is server-operator-only, explicitly gated by MELI_WEBHOOK_ENABLED=1, reviewed MELI_WEBHOOK_TOPICS and MELI_MISSED_FEEDS_REPLAY_ENABLED=1. It uses the selected store's current verified token without refreshing it, and the existing shared request coordinator. The store scopes the offset. Event admission still resolves each event to its own store from its validated identity. No public replay endpoint, automatic scheduler, official write, or raw response persistence. Each invocation fetches at most 10 records; accept exact live path or observed history aliases (bare message ID and /marketplace/resource/items/ID/), strict app/topic/user/resource/received validation. Never use request.data, URL or header. Any invalid, unmapped or unavailable scope blocks the whole page; inspect with read-only evidence, never silently skip. Same durable inbox/worker, same official-ID dedup where IDs match. Entire page + offset/revision commit atomically, no provider call under DB transaction. Two-record overlap and reset to offset zero on short page; an empty valid page completes a scan, not proof of complete recovery. Offset drift/retention, expired receipt dedup and dead-letter handling remain limitations. Queue admission is conservative (32 active jobs including page). No automatic retry or background scan until real contract accepted. Actual official response and edge measurements are Phase B acceptance checks.
