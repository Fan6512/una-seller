# 浏览器商品采集插件 MVP 开发任务书

> 项目：Una Seller — Mercado Libre AI ERP  
> 版本：v0.4（2026-11-15，明确采集箱/产品库/产品列表边界）  
> 状态：需求基线，待实施  
> 适用客户端：Windows / macOS 上的 Chrome 与 Edge  
> 关联规范：[Foundation](../architecture/FOUNDATION.md)、[Cross Platform](../architecture/CROSS_PLATFORM.md)、[ERP MVP](../architecture/ERP-MVP.md)

## 1. 产品定位与边界

浏览器插件是 Una Seller 的商品采集入口，不是独立 ERP，也不是持续运行的自动爬虫。

用户在 Amazon 或 Mercado Libre 正常浏览商品时，插件识别商品卡片，在卡片下方显示“采集”按钮。用户主动点击后，插件采集商品详情并提交给 Una Seller 后端，商品进入 ERP **采集箱**（原“商品采集库”），不会自动进入整理后的**产品库**或已刊登的**产品列表**。

第一版坚持人工选择：
- 只采集用户明确点击的商品。
- 不自动搜索、自动翻页采集或后台批量爬取。
- 采集阶段不调用 AI，不翻译、不改写、不补造字段。
- Amazon 只作为竞品研究来源；实际经营平台仍然只有 Mercado Libre。
- 插件与桌面客户端、后端通过稳定 API 契约通信。

## 2. 支持范围

### 浏览器与操作系统

- Chrome、Microsoft Edge，均使用 Manifest V3。
- Windows 10/11 x64。
- macOS Apple Silicon arm64 与 Intel x64。
- 插件代码与数据协议跨平台共用；不为 Windows 和 macOS 分别开发两套插件。

### 商品来源

- Mercado Libre：首批站点 MLM（墨西哥）、MLB（巴西）、MLA（阿根廷）。
- **Amazon：第一版仅开发并验收美国站 `amazon.com`（包括 `www.amazon.com`）**；美国站为今后的主要采集来源。
- 其他 Amazon 国家站点首期不开发、不单独测试，也不得因为美国站通过就宣称其他站已验证。

## 3. 商品卡片采集交互

### 卡片识别

- 识别搜索结果页和类目列表页中的商品卡片。
- 在每个可识别商品卡片下方插入独立的“采集”按钮。
- 支持页面滚动、翻页、无限滚动和动态加载后新增的商品卡片。
- 使用 MutationObserver 等必要机制监听新增节点；避免重复注入按钮和重复绑定事件。
- 商品卡片无法可靠识别时不显示误导性按钮。

### 按钮状态

| 状态 | 显示 | 行为 |
| --- | --- | --- |
| 未采集 | 采集 | 用户点击后开始采集 |
| 采集中 | 正在采集 | 防止重复提交 |
| 已采集 | 已采集 | 可查看或按明确操作重新采集 |
| 部分采集 | 部分成功 | 显示缺失字段，允许重试 |
| 采集失败 | 重新采集 | 用户可再次发起 |

插件不得因为页面加载或滚动而自动采集商品。

### 采集流程

1. 用户点击商品卡片下方的采集按钮。
2. 插件读取当前卡片可见信息和商品链接。
3. 在不改变用户当前标签页、不打断当前浏览的前提下获取商品详情。
4. 提取图片、详细描述、五点描述和全部可获取的规格变体。
5. 对采集结果进行结构校验，并标记完整、部分成功或失败。
6. 将数据提交给 Una Seller Backend API。
7. 后端完成去重和持久化后，插件更新按钮状态。

详情获取可采用平台页面公开数据、当前页面可访问的数据结构或后台非活动标签页等方式。具体方式由各平台适配器实现；不得绕过验证码、登录限制、访问控制或平台反爬机制。

## 4. 第一版采集数据规范

### 必须采集的字段

| 字段 | 要求 |
| --- | --- |
| 来源平台 | Amazon / Mercado Libre |
| 来源站点 | Amazon 对应站点；Mercado Libre 的 MLM / MLB / MLA |
| 商品标题 | 保留来源页面原文 |
| 商品链接 | 保存原始 URL，并生成规范化 URL 用于去重 |
| 商品图片 | 主图和页面可获取的其他商品图片，保留顺序 |
| 商品价格 | 保存当前可见价格；无法获取时为空并标记 |
| 货币 | USD、MXN、BRL 等，按来源页面识别 |
| 商品分类 | 保存来源页面实际提供的分类信息 |
| 详细描述 | 保存页面提供的完整原始描述 |
| 五点描述 | 按条目和原始顺序保存 |
| 多规格变体 | 保存来源页面可获取的全部变体 |
| 变体属性 | 颜色、尺寸、型号等实际属性 |
| 变体图片 | 保存图片与对应变体的关系 |
| 变体价格 | 页面提供差异价格时，保存到对应变体 |
| 首次采集时间 | 后端记录 |
| 最近采集时间 | 每次成功更新时记录 |

### 明确不采集

- 销量。
- 评价数量、评价内容及评分。
- 卖家信息。
- 独立商品品牌字段。
- 独立商品 ID / ASIN 字段。

去重使用来源平台、来源站点和规范化商品 URL，不增加独立的外部商品 ID / ASIN 数据字段。商品标题或原始描述中自然出现的品牌文字不需要人为删除，但不得额外提取为品牌字段。

### 五点描述规则

Amazon 页面存在五点卖点时，逐条保存并保留原始顺序。

Mercado Libre 页面不一定存在独立的五点描述结构：
- 页面提供明确卖点列表时按原样保存。
- 页面没有提供时保存为空。
- 不得把普通描述拆分、改写成五点描述。
- 不得调用 AI 生成缺失内容。

### 多规格变体规则

每个变体独立保存：
- 规格属性组合。
- 对应图片。
- 对应价格及货币（来源页面有提供时）。
- 来源页面可识别的其他必要规格信息。

必须保留来源页面实际存在的组合关系，不得自行排列组合出不存在的变体。若页面只加载部分变体或无法读取全部变体，应标记为部分采集，不得显示为完整成功。

## 5. 图片处理

- 保存来源图片 URL、图片顺序和变体关联。
- 商品采集库应能显示图片预览。
- 如需下载并缓存图片，必须使用项目管理的文件存储路径，不得将图片二进制直接塞入商品 JSON。
- 图片下载失败不能导致其他商品字段丢失；应保留来源 URL 并记录图片状态。
- 不把来源图片的公开可见等同于拥有再发布权；后续刊登必须确认素材使用权。

## 6. 插件结构与通信

建议目录：apps/browser-extension/

职责：
- Content Script：识别商品卡片、注入按钮、读取页面数据。
- Background Service Worker：协调采集任务、认证、向 ERP API 发送数据。
- Platform Adapters：Amazon 与 Mercado Libre 分开维护 DOM/页面数据适配逻辑。
- Shared Types：与 ERP API 共用或校验同一份采集数据契约。

通信：
- 本地开发时连接本机 ERP API。
- 云端部署后连接配置的 HTTPS ERP API。
- 不允许插件直接访问数据库。
- 不允许将 ERP Token 注入商品页面的 window 环境。
- 配对/绑定采用最小必要流程；具体接口以 ERP MVP 的认证契约为准。

## 7. 去重与重复采集

唯一去重依据：

用户账户 + 来源平台 + 来源站点 + 规范化商品 URL。

重复采集时：
- 不创建重复商品记录。
- 更新最近采集时间。
- 使用新采集到的有效字段更新来源资料。
- 不因本次页面暂时缺字段而无条件覆盖已有完整字段。
- 保留采集状态和必要的错误信息，方便人工重试。

## 8. 权限与合规边界

- 只申请 Amazon 和 Mercado Libre 相关站点及 ERP API 所需的浏览器权限。
- 不申请无必要的全站访问、Cookie、浏览历史或标签页管理权限。
- 不读取或保存卖家账号密码、支付信息或不必要的个人数据。
- 不绕过验证码、登录墙、访问控制或平台限流。
- 不使用智赢、妙手的私有接口、密钥、Cookie、反编译代码或复制其商业实现。
- 两个附件只用于理解交互和技术思路；自研代码独立实现。

### 与产品三区及 AI 整理的边界

- 浏览器插件**只采集**用户点击的来源网页真实资料并提交至**采集箱**；不在浏览器采集时调用 AI、修改商品、生成可刊登草稿或发布平台商品。
- AI 文案/图片整理、人工补充字段、产品库草稿及多站点刊登均在桌面 ERP 的内置业务模块中分阶段实施；详见 [产品工作流与编辑器](PRODUCT-WORKFLOW-AND-EDITOR.md)。
- “采集成功”仅代表来源资料在 ERP 后端保存成功，**不意味着已经完成 AI 整理或 Mercado Libre 刊登**。

## 9. 第一版明确不做

- AI 商品分析、选品、翻译和改写。
- 自动搜索、自动采集、定时采集或无人值守批量采集。
- 自动刊登、自动定价。
- 订单、售前问答、售后消息。
- Amazon 店铺授权和 Amazon 卖家运营。
- 采集销量、评价、卖家、品牌和独立商品 ID / ASIN 字段。

## 10. 验收标准

1. Chrome 和 Edge 可在 Windows 与 macOS 加载插件。
2. Amazon.com 美国站商品搜索/类目卡片能显示采集按钮。
3. Mercado Libre MLM、MLB、MLA 商品卡片能显示采集按钮。
4. 页面动态加载新商品后，按钮能正确出现且不重复。
5. 用户点击后不改变当前浏览页面。
6. 商品标题、链接、图片、价格、货币、分类、普通详细描述、独立 Bullet Points（页面有则保留）和可获取的全部变体能正确保存。
7. 变体属性、价格、图片关联关系正确。
8. 缺失字段不伪造；不完整数据明确标记部分采集。
9. 商品成功进入 ERP 商品采集库。
10. 重复采集不产生重复记录。
11. 采集失败可由用户重新发起。
12. 插件和 ERP API 断开后，能显示明确错误，不假报成功。
13. Amazon.com 验证正常、验证码/阻断、地区或邮编限制、缺 BuyBox、变体缺图/缺价格等场景，正确区分完整、部分、失败；没有访问权限时仅记录无法验证，不伪造结果。
14. 商品详情解析优先插件本地执行；上传 ERP 的是结构化商品字段，不是完整页面 HTML。

## 11. 静态研究后确认的五项实施要求（v0.3）

以下是对 2026-11-15 智赢 / 跨境 ERP 助手**静态研究**所做的自研功能归纳，属于任务要求，不是允许复制第三方反编译代码、专有接口或内部请求签名。静态观察不保证当前页面运行效果，必须使用自研实现和可访问的 Amazon.com 页面验证。

### P1：商品卡片 → 详情的两阶段采集

**阶段 A：商品卡片展示时**
- 在 Amazon.com 搜索/类目/详情页识别商品卡片或当前商品，按需通过 MutationObserver 识别新增卡片。
- 仅插入“采集”按钮、准备来源链接和卡片已有的可见信息。
- 不因滚动、翻页、曝光自动请求商品详情，不自动入库。

**阶段 B：用户点击后**
- 如果当前就是商品详情页，优先利用已渲染的 DOM 和来源页面公开信息。
- 如果用户在商品列表页，通过商品链接由插件后台请求详情或在非活动标签页读取；不改变用户当前浏览标签页。
- 本地将详情解析为结构化字段，必要时补充图片、Bullet Points 和变体，再提交 ERP。
- 无法直接获取详情时，明确报错或标记部分采集；不得绕过验证码、登录墙或站点访问限制。

### P2：Amazon.com 多规格变体补全

- 第一优先级：从页面 DOM 和公开内嵌商品变体数据读取**实际存在的**属性组合、价格及对应图片。
- 如确认存在某些变体、但对应价格或图片缺失，可在本次用户主动采集范围内执行有限的补充详情请求。
- 补充请求需有明确的数量/并发上限、超时和停止条件；上游拒绝或出现 CAPTCHA、403、429 时停止，不尝试规避。
- 第三方静态研究出现的“8 个/批、最多 64 个”仅是第三方实现的观察值，不是 Amazon 官方限制或我们的固定配置。
- 无法确认的变体价格或图片留空并给出字段警告；绝不凭规格维度做笛卡儿积来编造变体。

### P3：普通详细描述与五点描述独立

- \`description\`：保存来源页面原始的普通详细描述，保留文字/段落顺序。
- \`bullet_points\`：保存 Amazon 页面提供的 Feature Bullets，按照真实条目、原始顺序储存。页面不一定正好五条，没有就留空。
- 不允许把 description 自动切成五点，不进行 AI 改写或补造。
- Amazon A+ / Enhanced Brand Content 是独立的图文内容，**不等于普通描述或五点描述，首版不单独采集 A+**。未来若需要另行立项。
- Mercado Libre 没有独立卖点列表时，\`bullet_points\` 留空。

### P4：Amazon.com 页面状态与错误分类

建议在插件内部将页面判为以下状态（命名为自研契约，不照抄第三方解析器）：

| 页面状态 | 处理方式 |
| --- | --- |
| normal | 正常继续解析 |
| captcha / blocked | 立即停止补充请求；提示用户手动解决后再采集，不报完整成功 |
| zipRequired | 提示地区/邮编影响价格或可用性；字段不完整则标记部分采集 |
| deliveryUnavailable | 可保存真实取得的资料；价格/变体缺失则标记部分采集 |
| buyboxMissing | 不臆造价格；可保存已取得的文本/图片并标记缺失 |
| unknown | 不推测页面含义，报明确错误或部分采集 |

同时覆盖超时、解析异常、DOM 改版、插件通信失败、ERP API 不可达。用户可主动重新采集；被阻断时不自动无限重试。字段缺失原因用短错误码和可读提示展示即可，暂不引入复杂遥测系统。

### P5：一次结构化入库与后端幂等

- 插件向自有 ERP 仅提交结构化采集结果：\`POST /api/v1/collections\`。
- 不照搬第三方的“远端防重检查 → 取得商业采集参数 → 多次写入”链路，也不上传整页 HTML 给 ERP。
- 使用后端现有唯一键（所属用户 + 平台 + 站点 + 规范化 URL）和 PostgreSQL 事务完成去重及有条件更新；部分采集不能把已有完整字段覆盖为空。
- 服务器返回本次新增/更新结果、保存后的完整/部分状态、缺失字段或错误摘要；前端按钮在**后端确认持久化之后**才显示已采集或部分成功。
- 浏览器侧为关联商品页面、变体允许临时使用来源 URL 中的 ASIN 等页面标识，但不增加持久化的独立商品 ID / ASIN 字段。
- 无需为了这个 MVP 增加独立防重服务、复杂任务队列或商业签名体系。

## 12. 开发顺序

### 端到端验收前提：ERP 接收与查看链路先可用

插件代码可以在独立分支准备，但不能把“按钮能显示/页面能解析”当成采集功能验收通过。

至少应先具备：
1. ERP Backend API 可启动，PostgreSQL 数据库已迁移，`POST /api/v1/collections` 可以保存一个包含图片、普通描述、Bullet Points、真实变体的结构化测试商品；重复提交不重复入库。
2. `GET /api/v1/collections` 和详情接口能实际读出已保存记录。
3. Tauri 2 桌面客户端商品采集库能连接真实 API，显示该测试商品和多规格关联；不得仅使用前端 Mock 数据冒充已入库。
4. 然后接入 Amazon.com 插件，完成用户点击 → ERP API 持久化 → 桌面端可见的完整闭环；再扩展 Mercado Libre。

尽量复用仓库已存在的 M0 桌面骨架和 Go 健康接口，不重建第二套应用。插件与 ERP 后端可并行推进代码准备，但正式验收必须串成一条真实链路。



- P1：插件基础骨架、权限和 API 连接。
- P2：Amazon.com 卡片识别与用户主动点击后的单商品详情采集。
- P3：Amazon.com 五点描述、多规格、变体图片/价格、页面状态与失败处理。
- P4：Mercado Libre 卡片识别与单商品详情采集。
- P5：Mercado Libre 多规格、描述和图片验收。
- P6：两个平台统一数据格式、去重、失败重试和跨平台回归。

每个阶段以一个可验证结果提交独立 PR。先完成单商品纵向闭环，再扩展平台页面，不为追求覆盖率提前堆复杂采集框架。
