> 2026-11-15 · 产品设计基线 · 待实施，不代表已验收  
> 依据：用户明确需求及四张智赢商品编辑窗口截图（交互/字段分类参考）；不复制第三方代码或界面。  
> 关联：[架构基线](../architecture/FOUNDATION.md) · [领域契约](../architecture/DOMAIN_AND_EXECUTION.md) · [开发路线](../architecture/DELIVERY.md)。

## 1. 产品定位与三个区域

核心业务：**采集 → AI 整理 → Mercado Libre 刊登 → 日常运营**。Amazon.com 美国站为优先商品采集来源；Mercado Libre MLM（墨西哥）、MLB（巴西）、MLA（阿根廷）是当前优先经营站点。

| 区域 | 对象 | 用户行为 | 边界 |
|---|---|---|---|
| **采集箱** | 未整理的外部来源商品，原始字段与采集状态 | 读来源资料、人工补充真实产品事实、调用 AI 整理、转产品库 | 来源快照不被 AI 或商品编辑覆盖 |
| **产品库** | 已整理的自有商品草稿，可重复编辑/刊登 | 文案、规格、图片、价格、成本、包装、站点属性、SKU 编辑；选择店铺与目标站点 | 一份商品不等于一个 Mercado Libre Item |
| **产品列表** | 已由官方接口确认成功发布的店铺/站点商品 | 查看真实平台 ID、链接、状态、价格库存及修改结果 | 待发布、处理中、失败目标不伪装成已刊登 |
| **刊登记录**（附在产品库和已发布列表，不必成为第 4 个主导航） | 每次店铺+站点业务目标的发布操作 | 查看 pending/processing/success/failed/needs_check、错误和重试 | 请求接收成功不等于各目标站点刊登成功 |

同一个来源商品可整理为多个自有商品；一个自有商品可面向多个账号及站点发布多条平台对象。采集来源、产品库实体、官方刊登实例各自有独立身份。**产品列表也包含账号原本已刊登、后来由官方只读接口同步的商品**；这些商品允许暂时没有关联自有商品或 Una Seller 刊登记录。

## 2. 四张智赢截图提供了哪些参考

这些截图是一个商品编辑长窗口的不同位置，只证明可见 UI 的功能组织，不能证明平台规则或隐藏后端行为。

| 截图中的可见内容 | 自研功能决定 | 优先级 |
|---|---|---|
| 顶部编号/分类与商品主图、场景图、空图片槽，白底/场景图尺寸提示 | 采集箱保留源图，产品库提供主图/附图/变体图分组、顺序和选择；图中的 800×800 / 750×1000 是竞品提示，**非官方通用要求** | P0 预览，P1 编辑 |
| 审核状态、上下架、安全等级、采集/原创/复制等标签 | 不复制成熟 ERP 的多层内部审核和风险状态；只做来源完整性、草稿准备度、官方发布状态与失败原因 | 按需 |
| CBT、MLB、MLM、MLC、MCO、MLA、MLU 标签及材质、类型、规格、品牌等属性 | 根据目标店铺获准站点和官方类目属性动态生成编辑表单；不因为 UI 有某站点标签就声称账号有权发布 | 刊登前 |
| 1688 采购参考、成本/净收益、尺寸重量、物流/特殊货物字段 | 将人工补充的采购与经营数据与来源采集字段分开；净收益未来基于已验证费用估算，不照搬竞品公式 | 产品库渐进 |
| 内部 SKU、库存、变体组合及对应图片表 | 自有 SKU/规格与来源变体分离；真实组合与对应图/价格不混用 | 产品库 |
| 英语、西语、葡语、中文标签；标题、短标题、关键词、五点、普通详情描述 | 按语种管理候选文案；主标题、卖点、详细描述分开；短标题/关键词只作为可选编辑项 | AI 文案 |
| 图片区、来源链接、操作历史 | 保留原始图片与处理版本；操作记录包括时间、动作、结果和必要变更，不保存截图中的 IP 等信息 | 按需 |

**界面建议**：不要复制 4 张截图拼成的超长表单。自研编辑页按“图片｜基础及人工补充｜AI 文案｜规格 SKU｜站点类目属性｜刊登记录”分区；只在相关操作时展示需要的字段。

## 3. 采集箱整理工作稿与 AI 候选

1. **来源快照不可覆盖**：采集箱 SourceProduct 保留来源 URL、标题、图片、分类、真实变体/价格、普通描述和原始卖点。
2. **M1-A 即可保存人工补充**：实际材质/功能/尺寸/重量/包装/成本/供应商备注/禁用描述独立保存在来源关联的 **CollectionWorkingDraft（整理工作稿）**，而不写回来源快照。用户关闭界面、刷新、重启后能恢复，不能因为未转产品库而丢失；这些补充不属于浏览器插件必采字段。
3. **M1-B 才启用 AI 文案生成**：用户从采集箱触发，读取来源快照 + 整理工作稿里的事实 + 站点语言，生成可编辑的英文基础稿、es-MX、pt-BR、按需 es-AR 标题、卖点、普通描述和属性建议；**AI 候选保存在该工作稿中**，不会污染 SourceProduct。
4. 用户可按字段采纳、编辑、重新生成或拒绝；任何自动生成不得覆盖已人工确认的内容。
5. 点击“保存到产品库”才建立独立 OwnProduct 草稿，并复制用户选定的信息；**来源记录与整理工作稿仍可追溯**。采集箱默认筛选“未整理”，已整理记录可切换查看/再次整理；再次采集不能覆盖已整理草稿。
6. **产品库中也可以使用 AI 功能**：编辑页的 AI 文案分区复用相同生成能力，但生成/保存仅作用于 OwnProduct，不回写采集箱或来源快照。AI 不直接刊登。

保持既有标题规则：英文刊登输入建议 45–55 字符；MX 西语/BR 葡语买家标题优先不超过 60 字符且品类+核心关键词靠前。但**实际提交时必须按照当前站点、账号和类目的官方要求校验**；AI 不捏造材质、认证、功能、规格。

## 4. AI 主图一键白底

流程：选择具有相应使用权的图片 → 背景去除/抠图 → 纯白背景合成 → 原图/结果对比 → 人工确认使用。

- 保留原图、处理候选和最终选用版本；不得覆盖来源快照。
- 优先保持真实商品形状、颜色、包装和配件，不允许 AI 自由重绘重要细节。
- 官方卖家后台图片编辑、图片上传、图片诊断是不同能力。**当前未确认存在供第三方 ERP 公开调用的 Mercado Libre AI 白底生成 API**；实施时再核实具体 API、权限与适用范围，不能把诊断当修图。
- 首次交付先满足白底处理、对比预览、人工选择；批量修图、自动诊断、复杂素材仓库后置。

## 5. 店铺账号模板 + 多站点刊登

- **店铺账号**：官方 OAuth 连接，服务端保存 Token。
- **账号模板**：给店铺预设默认站点及按站点的价格/币种/物流、必要属性等销售条件；只配置实际使用的项。
- **本次刊登选择**：选择商品、账号、勾选该账号当前有权限的一个或多个站点，预览各站点差异后人工确认。
- 例子：店铺 A 默认 MLB+MLM；店铺 B 默认 MLB；店铺 C 默认 MLB+MLA。选择模板后可在账号有权限的范围内调整，不绕过平台授权。
- “西班牙”如指西班牙语应作为语言选择；西班牙（国家）并非这里的 Mercado Libre 经营站点。
- **一次勾选是用户操作**：真实 API 请求可一次包含多个站点（如 Global Selling 的多目标发布模型），也可能按账号能力拆分多个调用，**不预设一站点一请求**。后端必须逐目标记录结果，并解析官方按站点返回的状态（支持时含 `site_items[]`）；Global UP、Local UP、Item 关系以最新官方文档及账户能力为准。

## 6. 刊登状态、产品列表与失败定位

每次发布业务目标至少记录：产品库 ID、店铺 ID、站点、任务标识、时间、操作状态、官方对象 ID/链接（确认后）、失败错误码/字段原因、重试/回读情况。**一个官方创建请求可能关联多个目标站点；请求成功并不代表每个目标都成功**。

- 例如巴西发布成功、墨西哥失败：产品列表出现已核实的巴西发布对象；墨西哥留在“刊登记录”中，修正后只处理失败目标，不再创建已成功目标。产品列表也通过 OAuth 只读同步店铺既有商品，无需先关联产品库。
- 必须区分 pending / processing / success / failed / needs_check。超时或中断时先查官方结果，不能盲重发。
- 官方字段级错误（例如 cause[]）要转换为可读提示并定位到编辑器字段，保留可折叠的脱敏原始错误。
- 这属于刊登功能的强制验收，不能在首版只显示“提交成功”。
- 单后端 + PostgreSQL 持久化发布记录/必要任务即可，不预先搭消息总线。

## 7. 主程序 + 内置业务插件（轻量插件化）

主程序 Core 负责统一主题、导航、身份与 API 客户端、加载/错误、模块注册。**插件是构建时集成的功能模块**，可以独立开发、开启/关闭导航和路由；后端按同样领域划分路由包，共用一个进程和数据库。

功能模块：采集箱、产品库、AI 文案、图片处理、店铺/模板/刊登、已发布产品列表；后续按需增加订单、客服、运营统计。

浏览器 Chrome/Edge MV3 **扩展**与桌面 ERP 内置业务**插件**不是同一个东西。浏览器扩展采集并调用后端；**AI 文案插件可从采集箱整理工作稿或产品库编辑页触发**：前者的候选保存到 CollectionWorkingDraft，后者只写 OwnProduct，均不覆盖原始来源。

不做插件商店、第三方脚本动态安装、每插件独立后端/数据库、独立微服务、通用 SDK 或重型权限沙箱。出现真实扩展需求时再升级插件框架。
